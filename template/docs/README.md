# Project Documentation and Assurance Pack

This directory is the assurance pack for this application. It was generated by the
T40 Enterprise Application Starter and must be completed by the project team. Procurement
reviewers, security assessors and privacy leads should be able to answer their questions
from this pack without a meeting.

> This template supports evidence gathering; it does not by itself provide ISO 27001,
> SOC 2, Cyber Essentials, WCAG conformance or legal compliance. Certification and legal
> compliance require client-specific governance, contracts, operation and independent
> assessment.

## How to complete this document set

1. Every file with frontmatter `status: template` is unfinished. Complete it, set
   `status: complete`, and fill in `owner` and `review_by` (a review date, ISO 8601).
2. Assign a named owner to each document. "The team" is not an owner.
3. Complete the privacy set and the DPIA screening decision **before** production.
4. Complete a restore test and record it in `operations/backup-restore.md` **before**
   production.
5. Keep documents current: when the review date passes, review and either update or
   re-confirm the content.

## How this pack maps to controls

The installer writes `config/t40/control-manifest.yml` into this application. That file is
the authoritative record of which controls are enabled, verified, deferred (with owner) or
not applicable (with reason). This documentation set is the human evidence layer on top of
it:

| Control category | Primary evidence documents |
|---|---|
| authentication, session | `assurance/assurance-matrix.md`, generated request and system specs |
| tenancy, authorisation | `assurance/role-capability-matrix.md`, `assurance/assurance-matrix.md` |
| audit | `assurance/assurance-matrix.md`, `operations/access-review.md` |
| privacy | the whole `privacy/` set |
| uploads, headers, jobs | `assurance/assurance-matrix.md`, `architecture/threat-model.md` |
| observability | `operations/alerts.md`, `operations/ownership.md` |
| backup | `operations/backup-restore.md`, `operations/disaster-recovery.md` |
| delivery | `assurance/release-evidence.md`, CI workflow in `.github/workflows/` |
| incident | `operations/incident-response.md`, `SECURITY.md`, `public/.well-known/security.txt` |
| accessibility | `assurance/accessibility-checklist.md` |

Deferred controls in the control manifest name an owner. Each deferred control should map
to a section in this pack where the owner records the eventual decision and evidence.
